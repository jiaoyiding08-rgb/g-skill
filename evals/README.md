# 评测材料

本目录提供 72 个合成案例，每个 Skill 12 个。48 个用于开发，24 个标为 holdout_candidate。所有材料都在仓库中，作者可以看见，因此真实盲测集数量为 0。真实用户行为样本数量为 0。

`inputs/` 只包含问题、必要上下文、来源标记、模块和案例 ID。`grading/` 包含对应可接受决策、必须具备的内容、禁止行为和人工评审要求。独立 Skill 安装目录不包含评分答案。

## 如何检查

`python scripts/run_evals.py --mode offline --out .local/offline.json` 只检查六份预先写好的 JSON。它不解答 72 道题，也不评测模型。

真实模型评估需阅读 adapters/promptfoo/README.md 并显式授权。机械评分类只检查 Schema、模块和可接受决策，不能判断建议是否可行、归因是否可靠或措辞是否尊重用户。

人工评审逐个看 must/must_not，保留证据和反例。不能只看自动 score=1。报告必须给出样本来源、模型、运行时间、参数、工具、成本、失败数和未评审数。

## 真正独立的留出

由未参与改写的维护者，准备新的匿名任务并存放在执行代理与优化器不可读的位置。优化期间只提供开发集反馈。最终冻结候选后，由独立执行/评分程序一次性运行留出。

公开的 24 道候选题可以当未来留出设计模板，但不能在已经读过后仍称为盲测。此次没有生成“提升百分比”。

## 案例来源说明

题目受本次产品对话中的任务类型启发，并经过合成改写。没有把客户资料、私人健康记录或可识别成员记录放进测试文件。题目中的数字按合成场景处理，不代表真实交易记录。
