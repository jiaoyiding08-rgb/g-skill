# 外部核验与工具接口设计

**状态：未实现，不访问真实账户。**

未来核验请求应绑定 run_id、contract_id/version、criterion_id、证据目标、授权账户/范围、核验时间和有效期。核验器先确认权限，再读取最小必要外部状态。

结果应给出 passed/unknown/failed、供应商记录 ID、状态时间、可解释摘要、撤销或重查条件。API 200 只能证明请求被处理，不能代替业务状态。录屏和页面截图不能代替已提交的数据记录。

工具执行与效果核验分离。发布、发送、付款和删除需要各自授权。建议优先开发只读发布状态或本地 Git 状态，避免第一版接管支付。

E2/E3 回执需要可信核验服务和真实证据来源。不能由用户随便填一个 checked_by 字段就接受。生产版本需认证、权限、幂等、时间、防重放、异常停止和审计。

在该接口实现之前，当前 Python 底座对需要外部或人工核验的条件保持 WAITING_EVIDENCE，不允许以文本或哈希代签。
